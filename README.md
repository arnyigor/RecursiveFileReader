# Recursive File Reader

Создаёт один Markdown‑файл из всех исходных файлов заданной директории.
Подходит для быстрого сбора кода в формате, удобном для публикации на GitHub,
Bitbucket, GitLab и др.

---

## 📄 Описание

`main.py` рекурсивно ищет файлы с указанными расширениями  
(по умолчанию только `.kt`) и формирует из них один Markdown‑документ.  

Каждый файл представлен как:

```markdown
### `path/to/file.kt`

```kotlin
<содержимое файла>
```

*Заголовок* (`###`) содержит относительный путь к файлу,  
а блок кода оформлен с указанием языка (`kotlin`), чтобы GitHub автоматически подсветил синтаксис.

---

## ⚙️ Функциональность

| Возможность | Что делает |
|-------------|-----------|
| Рекурсивный поиск | Ищет во всех поддиректориях указанной папки |
| Поддержка произвольных расширений | Можно задать список через запятую (`kt,java,.cpp`) |
| Вывод в один Markdown‑файл | Удобно для публикации или архивирования |
| Простые аргументы CLI | `-s`, `-e`, `-o` |
| Без внешних зависимостей | Работает только с стандартной библиотекой Python |

---

## 📦 Требования

* Python 3.8+  
* Никаких сторонних пакетов (используется только stdlib)

---

## 🚀 Установка и запуск

```bash
# Клонируйте репозиторий (или просто скачайте файл)
git clone https://github.com/arny/recursivefilereader.git
cd recursivefilereader

# Запустите скрипт из каталога с исходниками
python main.py -s src/ -o all_sources.md
```

### Параметры командной строки

| Аргумент | Описание |
|----------|----------|
| `-s, --source` | Корневая папка для поиска (по умолчанию `.`). |
| `-e, --extensions` | Список расширений через запятую. Точки не обязательны (`kt,java,.cpp`). |
| `-o, --output` | Имя выходного Markdown‑файла (по умолчанию `source_dump.md`). |

---

## 📚 Пример

```bash
python main.py \
  -s ./app/src/main/kotlin/ \
  -e kt,java \
  -o project_source.md
```

После выполнения будет создан файл `project_source.md`, содержащий все Kotlin и Java файлы из указанной директории.

---

## 🔧 Как это работает

1. **Сбор файлов** – скрипт использует `Path.rglob("*")` для рекурсивного поиска,  
   отфильтровывая по расширениям.
2. **Чтение содержимого** – каждый файл читается в UTF‑8; ошибки обрабатываются
   простым выводом предупреждения и пропуском файла.
3. **Формирование Markdown** – для каждого пути создаётся заголовок `###`,
   а затем блок кода с языком `kotlin` (можно изменить, если нужно другое расширение).

---

## 📈 Расширения

* Добавить новый язык подсветки: замените строку `"```kotlin"` на нужную (`"```java"`, `"```cpp"` и т.д.).
* Фильтрацию по имени файла или дате изменения – можно реализовать, дополнив функцию `collect_source_files`.
* Вывод в формат HTML с помощью Markdown‑пакетов (например, `markdown2`), если нужен веб‑документ.
